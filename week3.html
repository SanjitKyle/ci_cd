☁️ Week 3: Cloud Deployment to AWS with OIDC

Everything learned and configured for AWS OpenID Connect (Keyless Authentication) & S3 Deployments.

1. Why OIDC Instead of Static Access Keys?

OpenID Connect (OIDC): An industry-standard authentication protocol that lets GitHub Actions securely request short-lived temporary security tokens directly from AWS Security Token Service (STS) without saving any permanent passwords in GitHub Secrets.
Feature ❌ Static Keys (Old Approach) 🏆 OIDC with IAM Role (Production Standard)
Secrets in GitHub Permanent Access Key ID & Secret Access Key Zero static keys! Only the IAM Role ARN
Token Life Infinite (dangerous if leaked) Temporary (auto-expires in 15 to 60 mins)
Security Boundaries Whoever has keys can access AWS Restricted strictly to repository SanjitKyle/ci_cd & branch main
Maintenance Manual 90-day key rotation required Zero maintenance, automated rotation

2. Exactly What We Configured in AWS Console

The exact steps completed to set up our AWS infrastructure:

Phase 1: Added GitHub as OIDC Identity Provider

  • Navigated to IAM ➔ Identity providers ➔ Add provider.
  • Selected OpenID Connect.
  • Provider URL: https://token.actions.githubusercontent.com (clicked Get thumbprint).
  • Audience: sts.amazonaws.com.
  • Created ARN: arn:aws:iam::194722438900:oidc-provider/token.actions.githubusercontent.com.

Phase 2: Created IAM Role (GitHubActions-S3-DeployRole)

  • Navigated to IAM ➔ Roles ➔ Create role.
  • Trusted entity type: Web identity.
  • Identity provider: token.actions.githubusercontent.com | Audience: sts.amazonaws.com.
  • Restricted to: GitHub Organization/Username: SanjitKyle, Repository: ci_cd, Branch: main.
  • Attached Permission Policy: AmazonS3FullAccess.
  • Role ARN: arn:aws:iam::194722438900:role/GitHubActions-S3-DeployRole.

Phase 3: S3 Storage Bucket

  • Created globally unique S3 bucket (e.g., sanjit-backend-deployments-2026).
  • Region: ap-south-1 (Mumbai) / us-east-1 (N. Virginia).
  • Kept Block Public Access enabled for secure storage of zip builds.

3. Crucial Rules for OIDC YAML Workflows

Rule 1: Always add the OIDC permission
GitHub will not mint an identity token unless you declare: 
permissions:
  id-token: write
  contents: read
Rule 2: Use role-to-assume inside `with:`
Instead of aws-access-key-id, pass: 
uses: aws-actions/configure-aws-credentials@v4
with:
  role-to-assume: arn:aws:iam::194722438900:role/GitHubActions-S3-DeployRole
  aws-region: ap-south-1
