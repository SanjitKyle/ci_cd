🚀 Week 2: Production Power & AWS Prep

Your cheat sheet for Matrix Builds, Artifacts, Caching, and Docker.

1. The Matrix Strategy

What it is: A way to write one job in your YAML file, but have GitHub automatically run it multiple times across different environments (like different Node.js versions or Operating Systems) simultaneously.

Real World Goal: Prove your backend code works perfectly on Linux, Windows, and Mac before you deploy it.

YAML Template:

jobs: matrix_test: runs-on: ubuntu-latest strategy: matrix: node-version: [16, 18, 20] # Test 3 versions at once! steps: - name: Setup Node uses: actions/setup-node@v4 with: node-version: ${{ matrix.node-version }} # Injects 16, 18, and 20 dynamically

2. Build Artifacts (Passing Files)

What it is: Because every job gets a completely blank computer, files created in Job 1 do not exist in Job 2. Artifacts allow you to upload a file (like a ZIP package) from Job 1, and download it into Job 2.

Real World Goal: When you deploy to AWS, you must hand AWS a packaged ZIP file of your code. Job 1 builds that ZIP, and Job 2 downloads it to send to AWS.

YAML Template:

jobs: build_job: runs-on: ubuntu-latest steps: - name: Upload the Artifact uses: actions/upload-artifact@v4 with: name: my-backend-package # Give it a name path: backend-build.txt # The file you want to save deploy_job: needs: build_job runs-on: ubuntu-latest steps: - name: Download the Artifact uses: actions/download-artifact@v4 with: name: my-backend-package # Must match the uploaded name exactly

3. Caching & Optimization

What it is: GitHub Actions can save files (like downloaded packages or heavy folders) into a temporary "vault". The next time the pipeline runs, instead of downloading everything from the internet again, it just loads it instantly from the vault.

Real World Goal: Make pipelines run in 10 seconds instead of 5 minutes. This saves companies thousands of dollars in GitHub compute charges.

YAML Template:

steps: - name: Try to load Cache uses: actions/cache@v4 id: my-cache with: path: node_modules # The heavy folder we want to save key: my-project-cache-v1 # The unique password for this cache - name: Install Dependencies (Cache Miss) if: steps.my-cache.outputs.cache-hit != 'true' # Only run if cache is NOT found run: npm install

4. Docker in CI/CD (The Holy Grail)

What it is: A way to package your code, along with the entire operating system and all dependencies, into an indestructible "container" using a blueprint called a Dockerfile.

Real World Goal: If you run raw Node.js code on an AWS server, it might break because the server has the wrong Node version. If you hand AWS a Docker container, it is 100% guaranteed to run perfectly.

The Blueprint (Dockerfile)

This file sits in the root of your project and tells Docker how to build the container.

# Start with a computer that has Node 20 FROM node:20-alpine # Create a folder for our app WORKDIR /app # Run a command to setup the code RUN echo "console.log('Running in Docker!');" > server.js # Tell the container how to turn on CMD ["node", "server.js"]

YAML Template: Building it in GitHub Actions

steps: - name: Build the Docker Image run: docker build -t my-backend-app . - name: Test the Docker Container run: docker run my-backend-app
