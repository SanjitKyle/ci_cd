Pillar 1

Multi-Layer Pagination & Compound Indexing

Scale & Performance
❌ The Production Bottleneck

Running Model.find() loads 50,000+ records into Node.js RAM simultaneously. In odontogram-service, every record contains 32 3D tooth mesh arrays, causing Node process out-of-memory crashes.

✅ The Engineered Solution

Parallelized Promise.all([find().skip().limit().select(), countDocuments()]) with compound B-Tree indexing. Large heavy fields (teeth, audit history) are projected out on list endpoints.

📁 staff-service/src/controller/staff.controller.js (Offset Math) Controller Layer 
export const getStaff = async (req, res, next) => {
    try {
        const page = Math.max(1, parseInt(req.query.page, 10) || 1);
        const limit = Math.max(1, parseInt(req.query.limit, 10) || 10);
        
        // Supports both page-based and offset-based frontend pagination
        const offset = req.query.offset !== undefined
            ? Math.max(0, parseInt(req.query.offset, 10) || 0)
            : (page - 1) * limit;

        const { staffMembers, total } = await staffService.getAllStaff({ limit, skip: offset });

        res.status(200).json({
            success: true,
            data: staffMembers,
            pagination: {
                total,
                page,
                limit,
                offset,
                totalPages: Math.ceil(total / limit),
                hasNextPage: offset + limit < total,
                hasPrevPage: offset > 0 || page > 1
            }
        });
    } catch (err) {
        next(err);
    }
};
📁 odontogram-service/src/services/odontogram.service.js (Projection Optimization) Service Layer 
export const getAllOdontograms = async ({ page = 1, limit = 10, offset }) => {
    const pageNum = Math.max(1, parseInt(page, 10) || 1);
    const limitNum = Math.max(1, parseInt(limit, 10) || 10);
    const skipNum = offset !== undefined ? Math.max(0, parseInt(offset, 10) || 0) : (pageNum - 1) * limitNum;

    // Parallel query execution: find and count run concurrently in MongoDB
    const [odontograms, total] = await Promise.all([
        Odontogram.find()
            .select('-teeth -history') // 🚀 CRITICAL: Omit 32 heavy tooth arrays to save 90% bandwidth!
            .sort({ createdAt: -1 })
            .skip(skipNum)
            .limit(limitNum)
            .lean(),
        Odontogram.countDocuments()
    ]);

    return { odontograms, total, page: pageNum, limit: limitNum, offset: skipNum };
};
Pillar 2

Centralized Error Handling Architecture

Resilience & Uniformity
The Express 4-Argument Rule

In Express, normal middleware uses 3 arguments (req, res, next). Whenever any controller or middleware calls next(err) with an argument, Express immediately skips all remaining routes and executes the single middleware that has 4 arguments: (err, req, res, next).

📁 src/utils/AppError.js (The Operational Error Class) Utility 
class AppError extends Error {
    constructor(message, statusCode) {
        super(message); // Sets this.message in JavaScript Error

        this.statusCode = statusCode || 500;
        this.status = `${statusCode}`.startsWith('4') ? 'fail' : 'error';
        this.isOperational = true; // Marks as trusted operational error

        Error.captureStackTrace(this, this.constructor);
    }
}

export default AppError;
📁 src/middleware/error.middleware.js (Clean 18-Line Global Dispatcher) Middleware 
export const globalErrorHandler = (err, req, res, next) => {
    let statusCode = err.statusCode || 500;
    let message = err.message || 'Internal Server Error';

    // 1. Invalid MongoDB ObjectId format (e.g. GET /api/patients/123)
    if (err.name === 'CastError') {
        statusCode = 400;
        message = `Invalid ${err.path}: ${err.value}`;
    }

    // 2. Duplicate unique key in MongoDB (e.g. duplicate email or double booking)
    if (err.code === 11000) {
        statusCode = 409;
        const field = Object.keys(err.keyValue || {})[0] || 'Field';
        message = `${field} already exists. Please use another value!`;
    }

    // 3. Send unified clean JSON response
    res.status(statusCode).json({
        success: false,
        status: `${statusCode}`.startsWith('4') ? 'fail' : 'error',
        message
    });
};

export default globalErrorHandler;

Pillar 3

Request Validation Layer (Zod)

Input Security & Schema Guards
Testing / Dev Mode: .passthrough()

During development, validation only enforces critical fields (e.g. full_name) and uses .passthrough() so you can send dummy fields, test notes, or unformatted phone numbers freely without getting blocked.

Production Mode: Strict Stripping

In production, .passthrough() is removed. Zod strictly validates types and formats (10-digit phone regex, valid emails) and automatically strips unallowed fields (preventing Mass Assignment attacks like role: 'admin').

📁 patient-service/src/middleware/validate.middleware.js (Reusable Middleware) Middleware 
import AppError from '../utils/AppError.js';

export const validate = (schema) => (req, res, next) => {
    try {
        const parsed = schema.parse({
            body: req.body,
            query: req.query,
            params: req.params
        });

        // Replace request objects with cleaned, sanitized data
        if (parsed.body) req.body = parsed.body;
        if (parsed.query) req.query = parsed.query;
        if (parsed.params) req.params = parsed.params;

        next();
    } catch (err) {
        // Collect Zod field errors and pass to Centralized Error Handler!
        if (err.errors) {
            const errorMessages = err.errors
                .map(e => `${e.path.filter(p => p !== 'body' && p !== 'params').join('.')}: ${e.message}`)
                .join(', ');
            return next(new AppError(errorMessages, 400));
        }
        next(err);
    }
};

export default validate;
📁 patient-service/src/validations/patient.validation.js (Schema Definition) Schema 
import { z } from 'zod';

const objectIdRegex = /^[0-9a-fA-F]{24}$/;

// 1. Flexible Create Schema: requires name, allows any dummy data during testing
export const createPatientSchema = z.object({
    body: z.object({
        full_name: z.string({ required_error: "Full name is required" })
                    .min(1, "Full name cannot be empty"),
        phone: z.union([z.string(), z.number()]).optional(), // Accepts string OR number!
        email: z.string().optional(),
        gender: z.enum(['Male', 'Female', 'Other']).optional()
    }).passthrough() // 👈 Enables testing with any custom dummy keys!
});

// 2. URL Param Validation: Guarantees URL :id is a 24-character Mongo hex string
export const patientIdParamSchema = z.object({
    params: z.object({
        id: z.string().regex(objectIdRegex, "Invalid Patient ID format in URL")
    })
});

Pillar 4

API Gateway Security & Rate Limiting

Front Door Defense
1. Helmet Security Headers

Hides X-Powered-By: Express so hackers cannot detect your framework. Sets X-Frame-Options: SAMEORIGIN to stop Clickjacking attacks in hidden iframes.

2. HPP Parameter Protection

Prevents parameter pollution like ?page=1&page=2, which causes Express to parse an Array and crash mathematical offset calculations with NaN.

3. Tiered Rate Limiting

General API: 200 reqs / 15 mins.
Auth API: 10 attempts / 15 mins.
Returns HTTP 429 Too Many Requests with standard reset headers.

📁 api-gateway/server.js (Complete Production Gateway Setup) API Gateway 
const express = require('express');
const dotenv = require('dotenv');
const { createProxyMiddleware } = require('http-proxy-middleware');
const cors = require('cors');
const helmet = require('helmet');
const hpp = require('hpp');
const rateLimit = require('express-rate-limit');

dotenv.config();
const app = express();

// 1. Global Security Headers (Always first!)
app.use(helmet());

// 2. Prevent HTTP Parameter Pollution (?page=1&page=2)
app.use(hpp());

// 3. CORS Configuration
app.use(cors({
    origin: '*',
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS'],
    allowedHeaders: ['Content-Type', 'Authorization', 'X-Requested-With', 'Accept', 'Origin']
}));

// 4. Tier 1: General API Rate Limiter (200 requests / 15 minutes)
const generalLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 200,
    standardHeaders: true,
    legacyHeaders: false,
    message: {
        success: false,
        status: 'fail',
        message: 'Too many requests from this IP, please try again after 15 minutes.'
    }
});
app.use('/api', generalLimiter);

// 5. Tier 2: Strict Auth Rate Limiter (10 login/register attempts / 15 minutes)
const authLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 10,
    standardHeaders: true,
    legacyHeaders: false,
    message: {
        success: false,
        status: 'fail',
        message: 'Too many login attempts from this IP. Please try again after 15 minutes.'
    }
});

// Proxy to Auth Service (Protected by strict authLimiter)
app.use(createProxyMiddleware({
    pathFilter: '/api/auth',
    target: process.env.AUTH_SERVICE_URL || 'http://127.0.0.1:5001',
    changeOrigin: true
}));

// Proxy to Patient Service
app.use(createProxyMiddleware({
    pathFilter: '/api/patients',
    target: process.env.PATIENT_SERVICE_URL || 'http://127.0.0.1:5002',
    changeOrigin: true
}));

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => {
    console.log(`API Gateway running on port ${PORT}`);
});
